## Reviewed invariants with no new defect found

- Non-finite floor, component, wall, route, reference and calibration coordinates are rejected at normalization boundaries. JSON cannot encode `NaN` or infinity.
- IDs are required and unique within every typed collection; port IDs are unique within their owning component, and endpoints use the component/port pair.
- Component XY movement and floor-Z rotation both re-derive attached route endpoint caches. Persisted cache drift is rejected.
- Route crossings and coordinate overlap do not create connectivity. System, stream, semantic role, floor and shared occupancy are explicit.
- Wall deletion preserves shared nodes, removes only orphaned candidates and rejects explicit surviving wall references.
- Command application clones validated state before mutation, so tested invalid joins, splits, deletes and calibration changes fail atomically.
- Portable open validates the complete package before active-project replacement. Package-level authority fields remain rejected and portable files restore no tenant or workflow authority.
- DXF-derived geometry remains an independent locked reference projection. It cannot create wall, room, connection, quantity, review or issue authority.
- DXF snap candidates are immutable query results. No wall exists until the ordinary Wall command is explicitly committed from user-selected points.

## Residual risks and limits

1. A bounded browser pass verified ordinary wall hit order, shared-node pointer movement, wall-draft cancellation, component placement/selection/rotation, typed supply/extract routing, invalid-route atomic rejection, route cancellation, shared-camera zoom/pan/Fit and the A3 SVG preview. DXF/PNG file-picker flows, stale-selection messaging, reference snap hit testing, CAD arc/bulge appearance, omission-warning placement, modal focus, actual download/open prompts, label legibility across viewport sizes and assistive-technology behaviour remain unverified.
2. PNG checking is an integrity-envelope check, not a complete PNG decoder or malware scan. Chunk CRCs, decompression behaviour and browser decode success are not independently proven.
3. The 32 MiB portable text cap bounds input size. DXF geometry counts are separately capped, but general JSON nesting depth and non-DXF entity counts are not; deeply nested crafted project JSON may still consume disproportionate CPU before validation finishes.
4. Device-local storage is a reversible recovery adapter. It is not encrypted storage, a transaction log, account sync, tenant isolation, authorization or a substitute for server save versions and immutable snapshots.
5. The localhost server has no authentication and must remain development-only on `127.0.0.1`. The path tests are unit-level; no live browser/socket security assessment was run.
6. Wall dependency discovery remains a conservative field-name scan for `*wallId`/`*wallIds`. Typed hosted openings, offsets and reassignment rules are not implemented.
7. Current schemas tolerate additional non-authority fields for forward experimentation. A closed production schema and nested authority-field policy remain later work.
8. `src/domain/spatial.mjs` and `app/main.mjs` are becoming large. The new controller, catalogue and static-path modules reduce immediate coupling, but later bounded extraction of wall, route/reference validation and renderer adapters is advisable before feature volume grows. No broad rewrite was justified in this review.
9. In-memory undo history is bounded to 50 prior snapshots and a 32 MiB estimated snapshot budget, keeping at least one prior state. It is still not durable; production checkpoint, collaboration and large-project memory policies remain unresolved.
10. The A3 output is an SVG working-draft preview only. It has been rendered in the localhost browser and visually inspected at one viewport, but it has not been printed, checked for font substitution across platforms, converted to PDF, compared against a physical scale ruler or assessed with assistive technology.
11. The scene fingerprint is deterministic FNV-1a for local equality checks, not a collision-resistant artefact checksum. Issued artefacts still require a cryptographic hash and immutable snapshot/issue workflow.
12. Uncalibrated references are included only as an explicitly display-only footprint and force the complete sheet to NTS. They must not be used for measurement; a trusted numeric scale requires calibration or reference removal.
13. The DXF adapter is intentionally a hand-bounded synthetic `AC1015` fixture parser, not general CAD support. It accepts only 7-bit ASCII and a small 2D entity subset; it does not support real-file/codepage validation, `MTEXT`, dimensions, hatches, splines, ellipses, legacy/3D polylines, paper space, external references, arrays, non-uniform inserts, DWG or IFC. The bounded shell review UI does not widen that compatibility.
14. The two recorded binary DWG candidates were not opened, converted or used as evidence. Their units, layers, geometry, external references and integrity remain unverified under DEC01.
15. The exact 32 MiB envelope is now the binding project-growth limit, while raw PNG/DXF and entity limits remain additional ceilings. This closes the silent post-growth exportability gap, but it is still a reversible prototype capacity—not a production file-size, performance or customer-plan promise. Oversized legacy drafts require user-directed size reduction before export; no reference-removal workflow is implemented in this milestone.

## Exact residual limits

- Portable envelope: 33,554,432 UTF-8 bytes total, including project JSON, base64/source text, derived geometry, nested escaping, indentation and metadata.
- PNG: 5,242,880 decoded bytes per asset, eight assets maximum, 20,971,520 decoded bytes total; the envelope may bind earlier.
- DXF: 4,194,304 source bytes per asset, four assets maximum, 12,582,912 source bytes total; the envelope may bind earlier. Parser limits remain 250,000 group pairs, 50,000 source entities, 100,000 emitted entities, 200,000 recursive visits, 250,000 vertices, depth eight and 2,000 diagnostics.
- Command history: 50 prior snapshots and 33,554,432 estimated snapshot bytes, retaining at least one prior state; history is not durable.
- Oversized legacy state: data remains locally recoverable and export-blocked; commands may not increase exact envelope bytes. No automatic deletion, compression or downgrade occurs.
